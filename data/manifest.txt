#
# Expectations are `key=value` pairs matched against the `summary` line that
# `cargo run --example replay` prints, and checked by `data/fetch.sh --check`.
# They are what makes "the only log that exercises StepTooLong" a claim the build
# enforces rather than a comment that quietly goes stale.
#
# `key=lo..hi` pins a value between two inclusive bounds. `data/expect.sh` owns
# the syntax and the comparison, and `data/scenarios.txt` writes its ceilings in
# the same language. The statistics below are pinned that way rather than
# exactly, because what a nis= key claims is about a receiver and not about a
# build, and a range is what states it.
#
# heading= is Validity::heading as initialization left it, not as the log
# ended. Only a magnetometer observes the rotation about gravity, and the
# covariance cannot say so on its own -- Initialization::sigma_yaw is 0.35 rad
# against an Accuracy::heading of 0.52, so a yaw nobody measured clears the bar
# comfortably. Every log here carries a magnetometer in its window, so every
# static one is valid; the key is what would notice if one stopped. Taking it
# at the end of the log instead would say only that some heading was fused at
# some point, which transitions= already notices.
#
# aligned_at= is seconds from the end of the initialization window to the
# first epoch Eskf::is_aligned read true, or never. It is what settled the
# alignment bars off the corpus the way replay settled
# Timeouts::degraded_after: with tilt equal to Initialization::sigma_tilt and
# heading equal to sigma_yaw, compared with <=, every static log here read
# 0.00 and lost the claim one step later. The bars are ALIGNED_TILT, 3
# degrees (PX4's own), and ALIGNED_HEADING, 30, and the static logs read
# 0.00 -- a window that observed gravity and a magnetometer is aligned when
# it closes. They are constants, not Config::accuracy, so a mission bar
# cannot move this key.
#
# 2c42096b is the one non-zero value, 0.20, and the wait is the heading's
# rather than the tilt's: its window is moving, so nothing established a
# heading there and Validity::heading waits for the first fused magnetic
# heading. Tilt was already under the bar when the window closed, because
# what bounds a coarse tilt is what that window's average supports and not
# the worst sample in it (#77). It read never until then, on a prior that
# nothing could bring under the alignment bar.
#
# attitude_lost= is the mission's side of the same question, added with
# covariance propagation: seconds to the first epoch at or after alignment
# where Validity::attitude read false against Config::accuracy, or never.
# It exists because nothing else on this line moves when it does --
# Status::Aligning latches deliberately (Eskf::is_aligned), so the growth of
# (16)-(22) would otherwise be invisible to the corpus, which has no truth to
# score against and only bookkeeping to check. Replayed at an Accuracy of 2.5
# and 25 degrees instead, the five logs below read 2.90, 1.49, 2.92, 0.78 and
# 2.90 with aligned_at= and transitions= unmoved: the two bars are two bars.
#
# It varies by what the vehicle was doing, which is the evidence that it
# measures the covariance rather than the clock. Unaided, the two logs with no
# GNSS position, which are handled rather than flown, read 1.70 s and 0.82 s
# (7592c9b2 starts at roll 2.94 pitch 6.56). A body-frame attitude covariance
# rotates with the body, so a 20-degree yaw prior becomes partly a tilt prior
# as the vehicle turns. Unaided, the other three read 3.82 s, 3.84 s and
# 3.82 s, and 2c42096b landing with the quiet ones was the point of #77: a
# vehicle vibrating on the spot starts from a prior the size of a quiet one's.
#
# Fusing GNSS position (23)-(28) moved only those three, to 5.78 s, 12.64 s
# and 3.93 s. A fix measures position, so it reaches tilt only through (17),
# in proportion to the horizontal acceleration the vehicle makes: the
# vibrating 2c42096b gained 0.11 s, 3949f175 1.96 s and a299e722 8.80 s. A
# position fix delays the loss and does not prevent it.
#
# Fusing GNSS velocity (29) moved the same three again, to 13.44 s, 58.14 s
# and 6.10 s. It is one integration nearer to tilt than position and more than
# doubled the time on every log that carries it, but it did not make any of
# them read never: a velocity observation constrains tilt only while the
# vehicle accelerates, and between manoeuvres the gyroscope bias prior grows
# the attitude block back through (20)'s -I dt.
#
# Magnetic heading (34)-(36) is what finally answers it, and it answers it
# differently per log rather than for the corpus. Two now read never -- 3949f175
# from 13.44 s and a299e722 from 58.14 -- because observing yaw stops the
# gyroscope bias prior growing the attitude block back through (20) between
# manoeuvres, which is the mechanism every paragraph above ran into. The two
# handled logs gain but do not reach it, 1.70 s to 3.84 and 0.82 to 3.87: a
# magnetometer pins the rotation about gravity and nothing measures gravity
# itself after the window closes, so what is left of the growth is the tilt's
# and a heading cannot stop it. 2c42096b barely moves, 6.10 s to 6.16, and its
# entry below says why -- it adopts its first heading rather than fusing one,
# so the yaw it gains arrives once and its tilt prior is untouched.
#
# rejected= is the gate's verdict and discarded= is everything that never
# reached it -- a variance of zero or less, a NaN, an altitude with no
# reference. Nothing on this line reported either before: refused= and
# invalid= count propagation steps, not measurements, so a change that began
# turning down every fix in the corpus would have passed --check unmoved.
#
# It was zero on every log while GNSS position was the only gated source, and
# at every gate #36 tried: 95 %, 99 %, 99.9 % and 5 sigma. The largest GNSS
# position test ratio at 95 % is 0.33, and the mean is 0.0023-0.0449 where a
# consistent R would put it near 0.38 -- PX4's eph and epv are far wider than
# the innovations they come with. Gates::default carries the rest.
#
# Both figures were 0.21 and 0.005-0.02 when position was the only gated
# source, and they move for a reason worth keeping rather than a drift: every
# source that tightens P tightens S = H P H' + R, so the same innovation reads
# as a larger ratio. nis_gnss_pos= below is the maintained form of the claim,
# per log rather than as a corpus range, and stated as a distribution rather
# than as a distance from a threshold that itself moves.
#
# Velocity (29) is the first source whose reported accuracy is tight enough
# for the gate to reach, and it is non-zero exactly once: a299e722 turns down
# 278 of its 609 solutions. That entry has the measurement. It is the receiver
# rather than the gate, and the corpus sees it because examples/replay.rs
# passes each row's own variance straight through, which trusts a receiver
# further than either production estimator does. Both floor it -- PX4 at
# ekf2_gps_v_noise, 0.5 m/s (EKF/common.h:370, applied at
# EKF/aid_sources/gnss/gps_control.cpp:320), ArduPilot at _gpsHorizVelNoise
# 0.3 and _gpsVertVelNoise 0.5 (AP_NavEKF3_PosVelFusion.cpp:821-822, defaults
# at AP_NavEKF3.cpp:23-24) -- and either floor would have absorbed every one
# of these 278. Read at PX4-Autopilot c4e4ef98 and ardupilot 368dc0c4. The
# harness does not apply them, so the corpus says what receivers actually
# report rather than what this repository would prefer they reported. Whether
# that is the right policy for a corpus whose figures get compared against
# EKF2's is #105, and this line is what moves if it is decided the other way.
#
# rejected_<source>= splits that total four ways, and the split is what makes
# a moved total attributable: the corpus's 278 are all velocity's, and the
# position gate has turned down nothing in 5348 fixes. Without the split, a
# stage that adds a gated source arrives here as a larger number with nothing
# saying which source grew -- the reading ba= and bg= were split to avoid.
# They were pinned at zero for baro and mag before either fused, so a first
# non-zero would be a diff rather than a discovery -- the same order rejected=
# itself was pinned in (#83, before the gate existed). rejected_baro= stayed at
# zero when (30) landed and is now a live key on four of the five logs: 2026,
# 4407 and 294 altitudes accepted and none turned down, against a gate of 10.83
# at one degree of freedom. rejected_mag= is the same story at four times the
# volume: 49692 headings across all five logs, every one of them accepted. No
# key on this line is structurally zero any more, so a non-zero in any of the
# four is now a measurement rather than a stage landing.
#
# The total stays beside the parts and is not redundant. data/expect.sh fails
# a key named here and absent from the line, but never a key on the line that
# nothing here names, so a source whose own key nobody added to these entries
# would go unwatched. The sum is what notices.
#
# floored= counts variances raised to the diagonal floor of equation (42'), per
# entry rather than per covariance, and it is pinned at zero because zero is
# the claim. The floor is not part of the arithmetic: it is set well below the
# smallest variance any state reaches here, and math.rs::FLOOR is where that
# margin is measured per state group and recorded -- this note deliberately
# quotes no figure of its own, since adding or dropping a log moves them and a
# second copy would go on reading as evidence. A non-zero here says a
# covariance is being driven toward zero by something upstream
# -- an R far smaller than what the measurement observes, a source fused faster
# than it carries independent information -- and that the floor is masking it
# rather than protecting against it. The 2 h log is what makes the zero worth
# something: 1398114 epochs of propagation and fusion, not one entry raised.
#
# Nothing else on this line would notice. A floored variance makes the estimate
# more conservative and never less, so it widens the S of (24) and moves
# neither rejected= nor transitions=. Whole-file evidence backs the zero up:
# each of the five replay CSVs is byte-identical to the same log replayed by
# the filter without (42')'s floor, which is what a floor that never fires has
# to produce.
#
# discarded= is also what separates two logs that alpha0= reads the same way.
# 7592c9b2 is alpha0=none discarded=0: an LPE log with no barometer rows at
# all. 2c42096b is alpha0=none discarded=35575: a barometer that reports
# throughout, every row of it thrown away for want of a reference a moving
# window could not establish. Counted after the commit, because Diagnostics
# resets there -- what a log refuses before it initializes is the harness's
# startup order and not the flight.
#
# an= is a_n of equation (5'), the vehicle's own acceleration over the window,
# and says only whether one was measured. Only a start the filter classified as
# moving reports one, so an=none covers both "the start was static" and "no two
# samples in the window carried a GNSS velocity" -- which is why it is pinned per
# log rather than read as a property of the data.
#
# roll0=, pitch0= and yaw0= are the attitude of equations (5)-(7), in degrees,
# taken at initialization rather than at the end of the log for the reason
# heading= is. They are the only keys here that look at attitude at all, and
# what they would catch is a sign inverted in the down-positive convention, the
# levelling dropped out of (6), or a declination that stopped reaching the
# filter. A window carrying no magnetometer has nothing to observe yaw with, so
# yaw0=0.00 there and heading= says which case it is. Two decimals, rounded
# before printing so that an angle just below zero cannot print as -0.00 and
# read as a moved expectation.
#
# PX4 Flight Review public logs are CC BY 4.0, so a corpus can be pinned here and
# redistributed with attribution. The files themselves stay out of the repo
# (data/logs/ is gitignored); this manifest is what makes the corpus reproducible.
#
# To add one, fetch it once and commit the line the script appends:
#
#   data/fetch.sh --add 'https://cdn.logs.px4.io/<log-id>.ulg'
#
# Browse https://review.px4.io/ for a flight with GNSS, barometer and magnetometer
# active; https://review.px4.io/dbinfo is the same database as JSON, with a
# download_url per entry. Then:
#
#   uv run tools/ulog2replay.py data/logs/<log-id>.ulg -o data/logs/<log-id>.csv --reference
#   cargo run --example replay -- data/logs/<log-id>.csv
#
# Everyone else afterwards runs `data/fetch.sh`, which verifies against the
# checksums below.
#
# nis_<source>= is the mean normalized innovation squared per degree of
# freedom over every measurement the gate ran an update for, rejections
# included. 1 is a filter whose S describes its own innovations. It answers
# what rejected= cannot: a count of zero is equally consistent with an R that
# is right and with one a hundred times too wide, and three of the four gated
# sources read a measured zero there.
#
# What the corpus says is that no source here reports an R near the size its
# residuals earn, and the two directions are different problems. Every figure
# quoted here is what the run printed; the bounds beside each entry carry the
# margin, and reading them back would flatter the claim by 1 %.
#
# GNSS position reads 0.0059, 0.0255 and 0.1170 on the three logs that carry
# it, so S is 3-13x too wide in sigma -- and mostly R, since an aided filter's
# H P H' sits well under a several-metre eph. a299e722's velocity is the one
# that reads the other way, 7.5623, its sigma_v about 2.75x too tight; smaller
# than the 6x its own differenced positions suggest (#105) because S is
# H P H' + R and the state's own uncertainty dilutes a too-small R. The same
# receiver-diluted reading applies to every ratio above.
#
# The barometer reads 0.0068-0.2493 and the magnetometer 0.0025-0.1980, and
# those test a constant rather than a receiver: PX4 logs no variance for
# either, so tools/ulog2replay.py substitutes one. Nothing in this corpus
# tested whether those constants were anywhere near right until this key, and
# the answer is that both are conservative: the barometer's by 2.0-12.1x in
# sigma, the magnetometer's by 2.2-20.0x. Stated per source rather than as one
# range, because a joint 2-12x would understate the magnetometer's low end by
# two thirds on the very sentence #50 has to argue from.
#
# nis_over95_<source>= is the fraction above the 95 % chi-square quantile at
# that source's dimension -- 0.05 for a filter whose innovations are
# distributed the way S claims. It sits beside the mean rather than instead of
# it because the two fail differently, and it is a structural zero everywhere
# except a299e722's velocity at 0.6503: another key whose interesting value
# the one it does not have.
#
# nu_<source>_<axis>= is the mean innovation, per axis because a norm hides
# the sign and a signed offset is how a declination error, an uncontrolled
# lever arm and measurement latency each show up. Two are worth naming:
# a299e722 carries a standing -0.66 m east on its position and -0.0656 rad
# (-3.76 deg) on its heading, which is the shape #23 is about.
#
# acf1_<source>= is the lag-1 autocorrelation of the normalized innovation,
# averaged over the source's axes. 0 for the white sequence (24) assumes, and
# it is not white anywhere: 0.57-0.99 on GNSS position, 0.17-0.85 on the
# barometer, 0.18-0.99 on the magnetometer. Expected and not chased -- a 1 Hz
# receiver filters its own solution in time, and a 250 Hz magnetometer is
# sampled far faster than the field it reads changes. It is pinned so that a
# change in that character is visible, not because 0 is reachable.
#
# All four are pinned as ranges. Each bound is the measured value plus or
# minus the larger of 1 % and one unit in the last printed place, rounded
# outward -- the 1 % is data/scenarios.txt's margin and its arithmetic, and
# the unit is what keeps a band from collapsing on a value whose 1 % falls
# below the precision it is printed at. A value of exactly zero and the word
# none are pinned exactly, being discrete rather than measured. A nu= value
# inside a thousandth is pinned to -0.001000..0.001000 instead, because what
# is being claimed there is the absence of an offset rather than its size.
