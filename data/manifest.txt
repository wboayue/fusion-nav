# sha256  name  url  [expectations]
#
# Expectations are `key=value` pairs matched against the `summary` line that
# `cargo run --example replay` prints, and checked by `data/fetch.sh --check`.
# They are what makes "the logs that exercise an IMU gap" (coasted=) a claim the
# build enforces rather than a comment that quietly goes stale.
#
# `key=lo..hi` pins a value between two inclusive bounds. `data/expect.sh` owns
# the syntax and the comparison, and `data/scenarios.txt` writes its ceilings in
# the same language. The statistics below are pinned that way rather than
# exactly, because what a nis= key claims is about a receiver and not about a
# build, and a range is what states it.
#
# heading= is Validity::heading as initialization left it, not as the log
# ended. Only a magnetometer observes the rotation about gravity, and the
# covariance cannot say so on its own -- Initialization::sigma_yaw is 0.35 rad
# against an Accuracy::heading of 0.52, so a yaw nobody measured clears the bar
# comfortably. Every log here carries a magnetometer in its window, so every
# static one is valid; the key is what would notice if one stopped. Taking it
# at the end of the log instead would say only that some heading was fused at
# some point, which transitions= already notices.
#
# aligned_at= is seconds from the end of the initialization window to the
# first epoch Eskf::is_aligned read true, or never. It is what settled the
# alignment bars off the corpus the way replay settled a source's timeout:
# with tilt equal to Initialization::sigma_tilt and
# heading equal to sigma_yaw, compared with <=, every static log here read
# 0.00 and lost the claim one step later. The bars are ALIGNED_TILT, 3
# degrees (PX4's own), and ALIGNED_HEADING, 30, and the static logs read
# 0.00 -- a window that observed gravity and a magnetometer is aligned when
# it closes. They are constants, not Config::accuracy, so a mission bar
# cannot move this key.
#
# cd7e0001 is the one non-zero value, 0.04, and the wait is the heading's
# rather than the tilt's: its window is moving, so nothing established a
# heading there and Validity::heading waits for the first fused magnetic
# heading. Tilt was already under the bar when the window closed, because
# what bounds a coarse tilt is what that window's average supports and not
# the worst sample in it (#77). 2c42096b read 0.20 the same way while it was
# the coarse start, and never before #77, on a prior that nothing could bring
# under the alignment bar.
#
# attitude_lost= is the mission's side of the same question, added with
# covariance propagation: seconds to the first epoch at or after alignment
# where Validity::attitude read false against Config::accuracy, or never.
# It exists because nothing else on this line moves when it does --
# Status::Aligning latches deliberately (Eskf::is_aligned), so the growth of
# (16)-(22) would otherwise be invisible to the corpus, which has no truth to
# score against and only bookkeeping to check. Replayed at an Accuracy of 2.5
# and 25 degrees instead, the five logs then pinned read 2.90, 1.49, 2.92,
# 0.78 and 2.90 with aligned_at= and transitions= unmoved: the two bars are
# two bars.
#
# It varies by what the vehicle was doing, which is the evidence that it
# measures the covariance rather than the clock. Unaided, the two logs with no
# GNSS position, which are handled rather than flown, read 1.70 s and 0.82 s
# (7592c9b2 starts at roll 2.94 pitch 6.56). A body-frame attitude covariance
# rotates with the body, so a 20-degree yaw prior becomes partly a tilt prior
# as the vehicle turns. Unaided, the other three read 3.82 s, 3.84 s and
# 3.82 s, and 2c42096b landing with the quiet ones was the point of #77: a
# vehicle vibrating on the spot starts from a prior the size of a quiet one's.
#
# Fusing GNSS position (23)-(28) moved only those three, to 5.78 s, 12.64 s
# and 3.93 s. A fix measures position, so it reaches tilt only through (17),
# in proportion to the horizontal acceleration the vehicle makes: the
# vibrating 2c42096b gained 0.11 s, 3949f175 1.96 s and a299e722 8.80 s. A
# position fix delays the loss and does not prevent it.
#
# Fusing GNSS velocity (29) moved the same three again, to 13.44 s, 58.14 s
# and 6.10 s. It is one integration nearer to tilt than position and more than
# doubled the time on every log that carries it, but it did not make any of
# them read never: a velocity observation constrains tilt only while the
# vehicle accelerates, and between manoeuvres the gyroscope bias prior grows
# the attitude block back through (20)'s -I dt.
#
# Magnetic heading (34)-(36) is what finally answers it, and it answers it
# differently per log rather than for the corpus. Two now read never -- 3949f175
# from 13.44 s and a299e722 from 58.14 -- because observing yaw stops the
# gyroscope bias prior growing the attitude block back through (20) between
# manoeuvres, which is the mechanism every paragraph above ran into. The two
# handled logs gain but do not reach it, 1.70 s to 3.84 and 0.82 to 3.87: a
# magnetometer pins the rotation about gravity and nothing measures gravity
# itself after the window closes, so what is left of the growth is the tilt's
# and a heading cannot stop it. 2c42096b, then a coarse start, barely moved,
# 6.10 s to 6.16: it adopted its first heading rather than fusing one, so the
# yaw it gained arrived once and its tilt prior was untouched.
#
# Converting ImuNoise's gyroscope-bias walk to a density (#137) moved the three
# that still lose it by hundredths -- f16771dd to 3.86 s, 7592c9b2 to 3.89 s and
# 2c42096b to 6.21 s: what regrows the attitude block is the bias prior
# through (20), and a slower walk adds to it more slowly. 2c42096b reads
# 3425.34 since its still 0.80 s prefix became its start (#86). Of the other
# logs that carry GNSS, 3949f175, 89a498ce, eb799954, cd7e0001, 285ee2e7
# and a299e722 read never; of the three that lose it, 4b473e91's and
# 7ce66f0d's entries explain theirs, and the (24') paragraph 093e806a's.
#
# rejected= is the gate's verdict and discarded= is everything that never
# reached it -- a variance of zero or less, a NaN, an altitude with no
# reference. Nothing on this line reported either before: refused= and
# invalid= count propagation steps, not measurements, so a change that began
# turning down every fix in the corpus would have passed --check unmoved.
#
# It was zero on every log while GNSS position was the only gated source, and
# at every gate #36 tried: 95 %, 99 %, 99.9 % and 5 sigma. The largest GNSS
# position test ratio at 95 % is 0.33, and the mean is 0.0023-0.0449 where a
# consistent R would put it near 0.38 -- PX4's eph and epv are far wider than
# the innovations they come with. Gates::default carries the rest.
#
# Both figures were 0.21 and 0.005-0.02 when position was the only gated
# source, and they move for a reason worth keeping rather than a drift: every
# source that tightens P tightens S = H P H' + R, so the same innovation reads
# as a larger ratio. nis_gnss_pos= below is the maintained form of the claim,
# per log rather than as a corpus range, and stated as a distribution rather
# than as a distance from a threshold that itself moves.
#
# Velocity (29) is the first source whose reported accuracy is tight enough
# for the gate to reach: a299e722 turns down 266 of its 609 solutions, and that
# entry has the measurement. On the multirotors it is the only such log; the
# fast vehicles below reach every gate, for the three causes their entries
# name. It is the receiver
# rather than the gate, and the corpus sees it because examples/replay.rs
# passes each row's own variance straight through, which trusts a receiver
# further than either production estimator does. Both floor it, at the
# parameters and lines VelocityNoise::clamped cites. Replayed with those
# floors applied, the 278 it turned down before #137 read 0 under PX4's treatment (the 0.5 m/s floor
# and the separate sq(1.5f) vertical widening), 2 under that floor alone and
# 44 under ArduPilot's per-axis 0.3/0.5; transitions= goes 4 to 2 under all
# three.
#
# The harness applies neither, and #105 settled that it should not: PX4's
# 0.5 m/s floor sits above 13163 of the corpus's 13676 velocity solutions, so
# applying it would replace a receiver's own figure rather than bound it, and
# it would move data/scenarios.txt, whose simulated receiver reports 0.15 m/s
# and does not lie. r_policy=raw on every entry below carries that verdict.
# data/README.md owns the reasoning; what this line owes is the pin.
#
# rejected_<source>= splits that total by source, and the split is what makes
# a moved total attributable. On the eight multirotor and SITL logs it is 398:
# a299e722's 326 velocity solutions and 70 positions, and eb799954's 2
# headings. The four airframe logs add 2255, and their split names their
# causes -- 093e806a's 268 positions a receiver claiming 0.37 m, 7ce66f0d's
# 107 positions, 178 velocities and 1558 headings an attitude levelled wrong
# during a hand launch, 285ee2e7's 9 altitudes a tailsitter's back-transitions
# and the 3 positions and 4 heights its barometer pulled the estimate away
# from (the (24') paragraph below). 4b473e91 rejects nothing: the fixes
# timestamped inside its logging dropouts are refused as ahead of the state
# (discarded=6) rather than fused against it. Without Config::recovery (#116), and with
# every fix fused as white, and at the 0.1 m/s^2 accelerometer-bias prior #149
# replaced, the first three read 860,
# 881, and 1931 and 1742. Without the split, a
# stage that adds a gated source arrives here as a larger number with nothing
# saying which source grew -- the reading ba= and bg= were split to avoid.
# They were pinned at zero for baro and mag before either fused, so a first
# non-zero would be a diff rather than a discovery -- the same order rejected=
# itself was pinned in (#83, before the gate existed). rejected_baro= stayed at
# zero when (30) landed and through the first eight logs, 76915 altitudes
# against a gate of 10.83 at one degree of freedom. 285ee2e7 turned down the
# first 7, each within 1.5 s of a back-transition, and 7ce66f0d 76 more on an
# estimate already wrong: 83 in 101060 (115 since (23'), 9 and 106). rejected_mag=
# read zero on the first five, 49229 headings; eb799954 turns down two samples
# its entry describes, and 7ce66f0d 1558 against a heading it never had: 1560
# in 80713. No key on this line is
# structurally zero any more, so a non-zero in any of the four is a
# measurement rather than a stage landing.
#
# The total stays beside the parts and is not redundant. data/expect.sh fails
# a key named here and absent from the line, but never a key on the line that
# nothing here names, so a source whose own key nobody added to these entries
# would go unwatched. The sum is what notices.
#
# floored= counts variances raised to the diagonal floor of equation (42'), per
# entry rather than per covariance. It is zero on all thirteen logs, and was 21 on
# cd7e0001 until (23'), whose entry has the receiver that reached it. The floor is not part of the arithmetic: it is set well below the
# smallest variance any state reaches here, and math.rs::FLOOR is where that
# margin is measured per state group and recorded -- this note deliberately
# quotes no figure of its own, since adding or dropping a log moves them and a
# second copy would go on reading as evidence. A non-zero here says a
# covariance is being driven toward zero by something upstream
# -- an R far smaller than what the measurement observes, a source fused faster
# than it carries independent information -- and that the floor is masking it
# rather than protecting against it. cd7e0001 was the first case, and the
# first kind: a receiver claiming 0.43 mm/s, fused raw. The 2 h log is what
# makes the other zeros worth something: 1.4 M epochs of propagation and
# fusion, not one entry raised.
#
# Nothing else on this line would notice. A floored variance makes the estimate
# more conservative and never less, so it widens the S of (24) and moves
# neither rejected= nor transitions=. When the floor landed, whole-file
# evidence backed the zero up: each of the five replay CSVs then pinned was
# byte-identical to the same log replayed without (42')'s floor, which is what
# a floor that never fires has to produce.
#
# recovered= counts the adoptions of resets= that recovered from gate lockout
# (Config::recovery, #116) rather than establishing a quantity a start left
# unobserved. Zero on eight logs, and the other four are why the key is
# pinned apart: each names a cause the recovery does not remove.
# 4b473e91's 12, which followed its logging dropouts, went to 0 when (22')
# coasted them (#144). 093e806a's 26 positions, with no IMU gap, are
# its dishonest receiver: the covariance shrinks under an R 0.37 m claims, the
# gate locks, and every 7 s the filter adopts its way back. a299e722's 2 are
# the same kind of receiver, its entry says when. 7ce66f0d's 36
# are an attitude levelled wrong that no position or velocity reset can fix,
# which it goes on getting wrong between them. 285ee2e7's one is a GNSS height
# its barometer held 4 m away (the (24') paragraph below). A recovery
# on a log whose sources are honest is a finding against the covariance
# rather than a working filter, which is what a zero here guards. With
# Config::recovery off and Correlation::WHITE, every entry reads as it did before #116, byte for
# byte in both replay CSVs.
#
# discarded= is what says how much of a barometer alpha0= left unused.
# 7592c9b2 is alpha0=none discarded=0: an LPE log with no barometer rows at
# all. cd7e0001 and 7ce66f0d are alpha0=estimate discarded=3: the rows between
# their commit and their first fix, when there is no established height to
# read a reference against. Counted after the commit, because Diagnostics
# resets there -- what a log refuses before it initializes is the harness's
# startup order and not the flight.
#
# an= is a_n of equation (5'), the vehicle's own acceleration over the window,
# and says only whether one was measured. Only a start the filter classified as
# moving reports one, so an=none covers both "the start was static" and "no two
# samples in the window carried a GNSS velocity" -- which is why it is pinned per
# log rather than read as a property of the data.
#
# roll0=, pitch0= and yaw0= are the attitude of equations (5)-(7), in degrees,
# taken at initialization rather than at the end of the log for the reason
# heading= is. They are the only keys here that look at attitude at all, and
# what they would catch is a sign inverted in the down-positive convention, the
# levelling dropped out of (6), or a declination that stopped reaching the
# filter. A window carrying no magnetometer has nothing to observe yaw with, so
# yaw0=0.00 there and heading= says which case it is. Two decimals, rounded
# before printing so that an angle just below zero cannot print as -0.00 and
# read as a moved expectation.
#
# declination= is the one the harness configured, in degrees, read from the
# log's header: tools/ulog2replay.py writes the declination the log's EKF2
# applied, by EKF2's rule -- PX4's table at the first fix when EKF2_DECL_TYPE
# bit 0 is set, EKF2_MAG_DECL otherwise (ATT_MAG_DECL on LPE). The harness used
# -3.44 for every log until #141, and against EKF2 the median heading
# difference on the five real logs with GNSS then went from +7.89, +4.78,
# +4.42, -4.39 and -13.34 deg to +0.89, +0.00, -0.20, +1.05 and +2.45
# (a299e722, 2c42096b, 89a498ce, eb799954, cd7e0001), read off the saved
# parameter. The table moved those five by at most 0.36 deg (2c42096b -8.22 to
# -8.58, a299e722 -10.81 to -11.13), the saved values being earlier table
# epochs. It matters where nothing was saved: 7ce66f0d, a first flight at its
# site, saved 0 and flew on -4.25. The two logs with no GNSS read 0.00, a site
# nobody looked up.
# Pinned beside yaw0=, which moves with it, because only this key says
# whether a moved yaw0 is the site or the filter.
#
# extent=, speed_max= and tilt_max= say what the vehicle did, so a note's
# "past a kilometre" or "pitched to the vertical" is pinned rather than
# asserted (#86). Extent is the farthest horizontal distance of any GNSS row
# from the first, speed the largest horizontal GNSS velocity, both as the
# receiver reported them, gated or not; none on the two logs with no receiver.
# Tilt is the filter's own estimate, the angle between body down and
# navigation down, so it reads a tailsitter's 90 deg where a ZYX pitch cannot.
#
# Being the filter's, tilt_max can say something about the filter, and it
# did. On 2c42096b, a grounded vehicle whose EKF2 attitude never leaves
# 1.08 deg of level, it read 5.2 at t=6475 s: the accelerometer bias walked to
# 0.56 m/s^2 under a sigma grown to 0.63, and tilt followed it, the two being
# indistinguishable on a vehicle that never accelerates. On f16771dd it read
# 15.8 at t=50.8 s, where EKF2 read 1.7. Both were ImuNoise's bias walks
# read as densities without conversion (#137). Converted, 2c42096b reads 2.5,
# a 3.5 g knock at t=4757 s, its ten-minute mean tilt holding 0.89 to 1.11
# deg; and f16771dd reads 11.9 at t=4.0 s, where EKF2 reads 11.8.
#
# PX4 Flight Review public logs are CC BY 4.0, so a corpus can be pinned here and
# redistributed with attribution. The files themselves stay out of the repo
# (data/logs/ is gitignored); this manifest is what makes the corpus reproducible.
#
# To add one, fetch it once and commit the line the script appends:
#
#   data/fetch.sh --add 'https://cdn.logs.px4.io/<log-id>.ulg'
#
# Browse https://review.px4.io/ for a flight with GNSS, barometer and magnetometer
# active; https://review.px4.io/dbinfo is the same database as JSON, with a
# download_url per entry; data/README.md, "Finding a candidate", says how to
# screen one against the gaps #86 names before it is added. Then:
#
#   uv run tools/ulog2replay.py data/logs/<log-id>.ulg -o data/logs/<log-id>.csv --reference
#   cargo run --example replay -- data/logs/<log-id>.csv
#   data/fetch.sh --pin <log-id>.ulg    # the expectations to append to its line
#
# Everyone else afterwards runs `data/fetch.sh`, which verifies against the
# checksums below.
#
# nis_<source>= is the mean normalized innovation squared per degree of
# freedom over every measurement the gate ran an update for, rejections
# included. 1 is a filter whose S describes its own innovations. It answers
# what rejected= cannot: a count of zero is equally consistent with an R that
# is right and with one a hundred times too wide, and most of the corpus reads
# a measured zero there.
#
# What the corpus says is that no source here reports an R near the size its
# residuals earn, and the two directions are different problems. Every figure
# quoted here is what the run printed; the bounds beside each entry carry the
# margin, and reading them back would flatter the claim by 1 %.
#
# GNSS position reads 0.0184-0.2251 horizontally on the four real logs whose
# position gate stays quiet and 0.0865-0.9207 in height, so S is 2.1-7.4x too
# wide in sigma horizontally -- and mostly R, since an aided filter's H P H'
# sits well under a several-metre eph. 89a498ce's RTK receiver reads 0.1139;
# 2b2ad123's, the other RTK log, reads 0.4503 and 0.0479 in height, its 18
# rejections being fixes that jump rather than an R that is wrong (its entry);
# and SITL 3949f175's 0.0034 and 0.0171 are a simulated receiver, not evidence
# about one. The four whose position gate turns fixes down read 0.59-45.45,
# and that is no claim about R: 093e806a's receiver is dishonest, 4b473e91's
# estimate went stale in a dropout, 7ce66f0d's was levelled wrong and
# 285ee2e7's barometer pulls its height away, and each entry says which. The two halves are gated and reported
# apart (GnssFusion), so each reads against its own degrees of freedom.
# 285ee2e7's height, the least conservative at 1.79, and 2c42096b's at 0.92
# are receivers measured against a height their barometer holds. a299e722's
# velocity is the one that reads the other way, 6.6705, its sigma_v about 2.6x
# too tight; smaller than the 6x its own differenced positions suggest (#105)
# because S is H P H' + R and the state's own uncertainty dilutes a too-small
# R. The same receiver-diluted reading applies to every ratio above.
#
# The barometer reads 0.0309-0.5164 on the ten real logs that carry one and
# whose estimate held (7ce66f0d's 1.0280 set aside), and the magnetometer
# 0.0026-0.9046 on ten of the twelve real ones (eb799954's 0.9983 set aside,
# two calibrations rather than one R, and 7ce66f0d's 25.27, a heading it never
# had), and
# those test a constant rather than a receiver: PX4 logs no variance for
# either, so tools/ulog2replay.py substitutes one. Nothing in this corpus
# tested whether those constants were anywhere near right until this key, and
# the answer is that both are conservative: the barometer's by 1.4-5.7x in
# sigma, the magnetometer's by 1.1-19.6x. Stated per source rather than as one
# range, because a joint figure would understate the magnetometer's low end on
# the very sentence #50 has to argue from.
#
# Estimating the barometric reference, (30') of #119, moved every consistency
# key on the three logs whose static window fixes one, and in one direction:
# the height innovations lost their mean. nu_baro_d went -0.1369 to -0.0275 on
# a299e722 and nu_gnss_hgt_d 0.3058 to 0.1580; on 3949f175 nu_gnss_hgt_d went
# -0.1076 to -0.0423 while nu_baro_d grew from -0.0020 to -0.0066, the two
# sources meeting in the middle rather than the barometer holding the height.
# That is what an offset the two disagree about looks like once something
# carries it. The largest of the rest are in the same channel: nis_gnss_hgt
# 0.0064 to 0.0048 and acf1_gnss_hgt 0.5489 to 0.6638 on 3949f175, nis_baro
# 0.2493 to 0.2093 on a299e722. Vertical velocity's mean innovation moves
# with them, 16 % on 3949f175 and 8 % on a299e722; f16771dd's heading mean
# moves 3 %, and the horizontal keys under 1 %. 7592c9b2 has no barometer
# rows at all, and 2c42096b is the paragraph below.
#
# 2c42096b was then a coarse start, so its window fixed no reference; the
# first altitude after its first fix read one from the estimate (#115),
# seeded correlated with the height it was read against by (30'). Its
# barometer was then fused throughout -- 4 rows discarded, all before that
# fix -- and the height keys moved as a second height source should move
# them: nis_gnss_hgt 0.0547 to 0.3125, nu_gnss_hgt_d 0.0638 to 0.1689,
# acf1_gnss_hgt 0.8883 to 0.9855, the receiver measured against a height it
# no longer set alone. rejected_gnss_hgt=0 and status=Healthy were the claim,
# and the negative control made them one: the same log at
# baro_offset_walk=0 rejected 3825 GNSS heights and ended Degraded. Its still
# prefix now fixes the reference (alpha0=window) and the claim holds the same
# way, nis_gnss_hgt 0.3163; cd7e0001 is the estimate's seed now.
#
# nis_over95_<source>= is the fraction above the 95 % chi-square quantile at
# that source's dimension -- 0.05 for a filter whose innovations are
# distributed the way S claims. It sits beside the mean rather than instead of
# it because the two fail differently. It sits under 0.05 on every log whose
# gates stay quiet except 2c42096b's GNSS height at 0.0624, a receiver the
# barometer holds the height against; the largest of the rest is 3949f175's
# heading at 0.0098. Where a gate does turn measurements down it reaches
# 0.6214 on a299e722's velocity and 0.8462 on 7ce66f0d's heading. Another key whose
# interesting value is the one it does not have.
#
# nu_<source>_<axis>= is the mean innovation, per axis because a norm hides
# the sign and a signed offset is how a declination error, an uncontrolled
# lever arm and measurement latency each show up. Two are worth naming:
# a299e722 carries a standing -0.40 m east on its position and -0.0957 rad
# (-5.48 deg) on its heading, which is the shape #125 is about; the east
# offset was -0.64 m until the log's own declination reached the filter.
#
# acf1_<source>= is the lag-1 autocorrelation of the normalized innovation,
# averaged over the source's axes. 0 for the white sequence (24) assumes, and
# it is white nowhere: 0.62-0.99 on GNSS horizontal position, 0.78-0.99 on
# GNSS height, 0.15-0.97 on the barometer and 0.16-0.99 on the magnetometer,
# with two that read the other way -- 89a498ce's RTK receiver, -0.28
# horizontally and -0.17 in height, and eb799954's two-stream magnetometer,
# -0.04. It is a statistic of the innovation rather than of the source, so
# the gain moves it: fusing every fix as white, GNSS read 0.62-0.99 and
# 0.67-0.99, the barometer 0.11-0.95, the magnetometer 0.09-0.99, the RTK
# receiver -0.34 and -0.23, and that is what Config::correlation's defaults
# were derived from. Expected and not chased -- a 1 Hz
# receiver filters its own solution in time, and a 250 Hz magnetometer is
# sampled far faster than the field it reads changes. It is pinned so that a
# change in that character is visible, not because 0 is reachable. The split
# of GNSS position into its two halves is where the figure says most:
# 2c42096b's receiver reads 0.8205 horizontally and 0.9857 in height, so
# the axis it wanders on is the one it is most correlated on -- the altitude
# that spans -7.49 to +19.80 m on a vehicle that does not move (#117).
#
# All four are pinned as ranges, and so are extent=, speed_max= and tilt_max=.
# data/fetch.sh --pin derives them (pin_pairs in data/expect.sh). Each bound is the measured value plus or
# minus the larger of 1 % and one unit in the last printed place, rounded
# outward -- the 1 % is data/scenarios.txt's margin and its arithmetic, and
# the unit is what keeps a band from collapsing on a value whose 1 % falls
# below the precision it is printed at. A value of exactly zero and the word
# none are pinned exactly, being discrete rather than measured. A nu= value
# inside a thousandth is pinned to -0.001000..0.001000 instead, because what
# is being claimed there is the absence of an offset rather than its size.
#
# #131 reads tilt and heading on navigation axes rather than body ones -- in
# Validity, the alignment latch, (36')'s levelling variance, the heading
# adoption and (8)'s prior -- and one log moves. f16771dd's nu_mag_yaw goes
# -0.027303 to -0.025485 and nu_baro_d -0.010923 to -0.010810, every other key
# inside its band. The heading mean is (36') alone: its tilt variance is the
# larger of two, and at yaw0=-107.33 the body pair and the north/east pair are
# rotated far apart, so an anisotropic tilt block gives each a different
# maximum. The barometer's is the two together -- reverting (8) alone reads
# -0.011038 and (36') alone -0.010689 -- through the attitude-height
# correlations both reach. No transitions=,
# aligned_at= or attitude_lost= moved on any log: the corpus starts within
# 6.56 deg of level, where the two splits differ at second order.
#
