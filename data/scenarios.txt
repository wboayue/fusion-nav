# scenario  seed  ceilings
#
# Ceilings on the `score` line `examples/replay.rs` prints for each scenario of
# `examples/simulate.rs`, asserted by `data/bench.sh` in CI. The simulator is the only source
# with truth to score against, so this file is where the crate says how accurate the filter is
# rather than how self-consistent -- `data/manifest.txt` is the other half, on real logs with
# no truth.
#
# `key<=v` is a ceiling, `key>=v` a floor; `data/expect.sh` owns the syntax and the comparison,
# and `data/manifest.txt` writes its expectations in the same language.
#
# Each bound is the measured value plus 1 %, rounded outward -- except `scored`, which is a count
# of matched truth rows rather than a float comparison and is pinned exactly, because slack there
# would weaken the guard against scoring the wrong file. The margin is not a fudge for an unknown:
# `examples/simulate.rs` is a host tool on `std`'s `sin` and `cos`, not the `libm` crate that pins
# the filter, and since (9)-(15) every figure here is an integral over tens of thousands of steps,
# so a platform whose last bit differs moves these numbers by roughly n*eps -- about 0.2 % over
# `mission`'s 36600 epochs. 1 % is five times that, and still thirty times smaller than the
# smallest move this file has ever recorded as real (`flight`'s pos_h fell 41 % when propagation
# landed). The measured values themselves live in the commit that moved them.
#
# Every number here was measured, and a change that moves one is a change that needs a sentence
# saying what the data said -- the discipline `data/manifest.txt` already holds. A breach of a
# fraction of a percent is the margin above being exceeded, which is a real move and not drift. Moves go both
# ways, and stage 3 moved them both ways at once: `flight` tightened across the board while every
# 185 s scenario loosened by an order of magnitude. That is what dead reckoning is. Holding the
# position at zero, which is what a filter that propagates nothing does, beats integrating a
# tilt error for three minutes; it loses to it over fourteen seconds.
#
# The `seed` column pins which flight produced these numbers. `examples/simulate.rs` owns the
# seed; `data/bench.sh` checks this column against the header the generator wrote, so changing
# a seed in that table invalidates the ceilings loudly rather than re-baselining them quietly.
#
# `baro_drift` and `mag_disturbance` carry `mission`'s numbers exactly, and that is the design
# rather than a copy-paste: both are one-variable departures from `mission` on `mission`'s seed,
# each departing in an aiding source whose `fuse_*` is still a stub. They start measuring their
# own departure at stages 7 and 8. The other departures separate now that GNSS position reaches
# the state. `gnss_outage` dead-reckons through its gap and reads `pos_h` 4.64 m to `mission`'s
# 0.70. `harsh_imu` hardly separates at all, because an aided filter no longer integrates its
# noise for three minutes.
#
# What is not here is a test of the covariance itself. A ceiling pins what the filter did last
# run, so it passes a filter that grew more accurate and more overconfident at once -- the
# failure that reaches the gate, the gain and `Validity`. That needs ANEES over N seeds against
# a chi-square bound: #89. The format is already indifferent to it -- lines are read as
# `name seed pairs`, and nothing assumes one line per scenario.
#
# What every figure measures today: equations (9)-(22) propagate, and GNSS position is fused
# through (23)-(28) at `Gates::default`'s 99.9 %. Velocity, barometer and heading are still
# stubs. Fusing position took every 185 s scenario from dead reckoning to aided navigation:
# `mission`'s `pos_h` 1261 m to 0.70, `static`'s 29.6 m to 0.67. The consistency keys rose toward
# the 1 a consistent filter reads, from below: `nees_pos` 0.0118 to 0.85 on `mission`. That is
# the direction `examples/simulate.rs` predicts, since `Q` is conservative against its IMU table.
# One line reads *over*confident, and it is meant to. `gnss_latency` delivers each fix late,
# which this filter does not model (GOALS.md, "Measurement latency"), so a fix is wrong by the
# distance flown in the delay and `R` does not say so: `nees_pos` 6.45, `in3s` 0.9467.
#
# `moving_start` is where the coarse start's overconfidence went. Before a measurement could
# correct anything, its position and velocity priors were `Initialization`'s 1 m and 0.1 m/s
# against a truth kilometres away, and it read `nees_pos=10.30` and `nees_vel=10.59`. The first
# fix is adopted (`Fusion::Reset`, once), and fused fixes after it bring both to 0.78 and 0.40.
#
# `false_valid` is non-zero everywhere, because an aided filter's sigmas now sit near the bars
# they are judged against. That is the regime the key exists for, and the bar is a 1-sigma one,
# so `examples/replay.rs` says to read it as a rate. Nearly all of it is horizontal velocity,
# which a position fix reaches only through the correlations of (20): 854 of `mission`'s
# 36600 epochs (2.3 %). `false_valid_att` stays small: 40 tilt epochs on `mission`, 0.1 %.
# `flight`'s 526 falsely valid heading epochs are gone, because position fixes carry the
# unobserved heading from 0.60 rad out to 0.09 rad within four seconds.
#
# `flight` is also the one line where fusing made a figure worse. `pos_v` went 0.72 m to 3.07,
# and `pos_h` 8.4 to 9.1. The window has no magnetometer, so heading starts 0.6 rad out, and
# the four seconds of fixes that correct it leave 0.39 m/s of error in vertical velocity. The
# fixes stop at 6 s, and the eight seconds of dead reckoning after them integrate that to
# 6.8 m. Unaided, the same fourteen seconds drifted 0.72 m from a velocity nothing had
# disturbed. The covariance covers the error throughout (`in3s=1.0000`). A heading the window
# observed, which is stage 8's, is the test of whether that is the cause.
