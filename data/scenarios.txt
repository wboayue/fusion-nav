# scenario  seed  ceilings
#
# Ceilings on the `score` line `examples/replay.rs` prints for each scenario of
# `examples/simulate.rs`, asserted by `data/bench.sh` in CI. The simulator is the only source
# with truth to score against, so this file is where the crate says how accurate the filter is
# rather than how self-consistent -- `data/manifest.txt` is the other half, on real logs with
# no truth.
#
# `key<=v` is a ceiling, `key>=v` a floor; `data/expect.sh` owns the syntax and the comparison,
# and `data/manifest.txt` writes its expectations in the same language.
#
# Every number here was measured, and a change that moves one is a change that needs a sentence
# saying what the data said -- the discipline `data/manifest.txt` already holds. Moves go both
# ways, and stage 3 moved them both ways at once: `flight` tightened across the board while every
# 185 s scenario loosened by an order of magnitude. That is what dead reckoning is. Holding the
# position at zero, which is what a filter that propagates nothing does, beats integrating a
# tilt error for three minutes; it loses to it over fourteen seconds.
#
# The `seed` column pins which flight produced these numbers. `examples/simulate.rs` owns the
# seed; `data/bench.sh` checks this column against the header the generator wrote, so changing
# a seed in that table invalidates the ceilings loudly rather than re-baselining them quietly.
#
# Six of the nine lines carry identical numbers, and that is the design rather than a
# copy-paste: `gnss_outage`, `baro_drift`, `gnss_latency` and `mag_disturbance` are
# one-variable departures from `mission` on `mission`'s seed, each departing in the *aiding*,
# and no aiding reaches the state while every `fuse_*` is a stub. `harsh_imu` separates through
# the initialization window, and now through propagation too: ten times the white noise is ten
# times the gyroscope-bias error the window leaves behind, and `pos_h` is 8.5x `mission`'s.
# They start measuring their own departure when the update of (23)-(28) lands;
# `examples/replay.rs` carries the reasoning.
#
# What is not here is a test of the covariance itself. A ceiling pins what the filter did last
# run, so it passes a filter that grew more accurate and more overconfident at once -- the
# failure that reaches the gate, the gain and `Validity`. That needs ANEES over N seeds against
# a chi-square bound, which needs a covariance that moves: #89, after #35. The format is
# already indifferent to it -- lines are read as `name seed pairs`, and nothing assumes one
# line per scenario.
#
# What every figure measures today: equations (9)-(15) dead reckon and nothing corrects them.
# The covariance has not moved since initialization, which is why `nees_*` reads in the
# thousands here and up to 3.9e7 on `harsh_imu` -- the error grows and the uncertainty it is
# divided by does not. Those keys are a regression guard on the error alone until #35.
