# scenario  seed  ceilings
#
# Ceilings on the `score` line `examples/replay.rs` prints for each scenario of
# `examples/simulate.rs`, asserted by `data/bench.sh` in CI. The simulator is the only source
# with truth to score against, so this file is where the crate says how accurate the filter is
# rather than how self-consistent -- `data/manifest.txt` is the other half, on real logs with
# no truth.
#
# `key<=v` is a ceiling, `key>=v` a floor; `data/expect.sh` owns the syntax and the comparison,
# and `data/manifest.txt` writes its expectations in the same language.
#
# Each bound is the measured value plus 1 %, rounded outward -- except `scored`, which is a count
# of matched truth rows rather than a float comparison and is pinned exactly, because slack there
# would weaken the guard against scoring the wrong file. The margin is not a fudge for an unknown:
# `examples/simulate.rs` is a host tool on `std`'s `sin` and `cos`, not the `libm` crate that pins
# the filter, and since (9)-(15) every figure here is an integral over tens of thousands of steps,
# so a platform whose last bit differs moves these numbers by roughly n*eps -- about 0.2 % over
# `mission`'s 36600 epochs. 1 % is five times that, and still thirty times smaller than the
# smallest move this file has ever recorded as real (`flight`'s pos_h fell 41 % when propagation
# landed). The measured values themselves live in the commit that moved them.
#
# Every number here was measured, and a change that moves one is a change that needs a sentence
# saying what the data said -- the discipline `data/manifest.txt` already holds. A breach of a
# fraction of a percent is the margin above being exceeded, which is a real move and not drift. Moves go both
# ways, and stage 3 moved them both ways at once: `flight` tightened across the board while every
# 185 s scenario loosened by an order of magnitude. That is what dead reckoning is. Holding the
# position at zero, which is what a filter that propagates nothing does, beats integrating a
# tilt error for three minutes; it loses to it over fourteen seconds.
#
# The `seed` column pins which flight produced these numbers. `examples/simulate.rs` owns the
# seed; `data/bench.sh` checks this column against the header the generator wrote, so changing
# a seed in that table invalidates the ceilings loudly rather than re-baselining them quietly.
#
# Six of the nine lines carry identical numbers, and that is the design rather than a
# copy-paste: `gnss_outage`, `baro_drift`, `gnss_latency` and `mag_disturbance` are
# one-variable departures from `mission` on `mission`'s seed, each departing in the *aiding*,
# and no aiding reaches the state while every `fuse_*` is a stub. `harsh_imu` separates through
# the initialization window, and now through propagation too: ten times the white noise is ten
# times the gyroscope-bias error the window leaves behind, and `pos_h` is 8.5x `mission`'s.
# They start measuring their own departure when the update of (23)-(28) lands;
# `examples/replay.rs` carries the reasoning.
#
# What is not here is a test of the covariance itself. A ceiling pins what the filter did last
# run, so it passes a filter that grew more accurate and more overconfident at once -- the
# failure that reaches the gate, the gain and `Validity`. That needs ANEES over N seeds against
# a chi-square bound: #89, which is now unblocked. The format is already indifferent to it --
# lines are read as `name seed pairs`, and nothing assumes one line per scenario.
#
# What every figure measures today: equations (9)-(22) propagate the state and its covariance,
# and nothing corrects either. The error keys are unchanged by covariance propagation, because
# the nominal state is -- `pos_h`, `pos_v`, `vel`, `pos_h_max`, `tilt` and `yaw` all still read
# what stage 3 measured. Everything derived from `P` moved, in the direction
# `examples/simulate.rs` predicted before it could be checked: the filter is *under*-confident
# against its IMU table, by about the two orders of magnitude that table says to expect
# (`nees_pos` 0.0118 on `mission` where a consistent filter reads 1), `in3s` is 1.0000
# everywhere, and `false_valid` is 0 outside `flight`. Under the `dt^2` discretization of (21)
# that both production estimators use, `Q` would be 200x smaller at this rate and `nees_*`
# would read near 1 -- so these numbers are also the evidence for the `dt` form, since the
# simulator's own noise table says under-confident is the only honest answer here.
#
# `moving_start` is the exception worth reading, and the only line #77 and #85 move at all --
# it is the only scenario that starts coarse. Its six error keys do not budge, since nothing
# about the nominal state changed; everything derived from `P` does. `nees_att` goes 0.0967 to
# 0.5164, five times closer to the 1 a consistent filter reads, and no attitude quantity-epoch
# is falsely valid before or after. That is the answer to what #77 asked: bounding a coarse
# tilt by the average equations (5)-(6) level, rather than by the worst sample in the window,
# is honest and not merely tighter.
#
# `false_valid` 0 to 115 is what it cost, and the breakdown says it is not the attitude: 7 on
# position (h), 108 on velocity (v), 0 on tilt and heading. A prior that wide grew the position
# and velocity blocks through (20) faster than dead reckoning grew the error, so the filter
# withdrew those two outputs before it was wrong about them. It no longer does, and what shows
# through is the overconfidence `nees_pos=10.26` and `nees_vel=10.56` were already reporting: a
# coarse start's position and velocity priors are `Initialization`'s 1 m and 0.1 m/s while the
# truth is kilometres away. Nothing is outside 3 sigma (`in3s=1.0000`), so those 115 epochs
# claim "usable to 5 m and 1 m/s" with an error inside three times the sigma they report and
# outside the mission bar they are judged on. Re-bounding those two priors is not this pass;
# #89's ANEES is the gate that would fail on it.
